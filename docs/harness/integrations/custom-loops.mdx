The harness needs exactly three touchpoints with your loop, whatever it is built with: the **system context** in the prompt, the **toolset** among the tools, and a **turn boundary**. No adapter required.

```python
from pandaprobe_harness import Harness
from pandaprobe_harness.agent_tools.native import as_anthropic_tools

harness = Harness.create()
```

`Harness.create()` provisions the workspace, wires every component (hook, mailbox, journal, rules, eval set, toolset, restricted shell), and schedules the startup health check. It accepts an explicit `HarnessConfig` and the two optional developer seams:

```python
from pandaprobe_harness import Harness, HarnessConfig

harness = Harness.create(
    HarnessConfig.from_env(capture_eval_cases=True),
    replay=my_replay_fn,      # counterfactual rule validation + regression runs
    verifier=my_grader,       # ground-truth outcome, decides promotion
)
```

## 1. The system context

```python
system_prompt = harness.system_context() + MY_PROMPT
```

Rebuild it **each turn** if you can — the mailbox banner and the References index are current-state.

<Note>
  The block is the [skill root](/harness/loop/rules-and-retrieval#the-skill-root) — protocol, tool table, and an index of the agent's rule files — plus the pending-notice banner. It carries **no rule bodies**, and takes no arguments: there is nothing to pre-select, because the agent conditions retrieval on the task itself with `harness_rules_search` and `harness_rules_read`.
</Note>

For static-prompt setups, the standing protocol's "work through pending notices before continuing" instruction is the trigger instead of the banner.

## 2. The tools

```python
specs, dispatch = as_anthropic_tools(harness.toolset)
tools = my_tools + specs
# on a harness tool call: result = await dispatch(name, args)
```

`as_langchain_tools` and `as_openai_function_tools` cover the other native formats, and the `pandaprobe-harness-agent` companion CLI covers sandboxed shells — see [the toolset](/harness/loop/agent-toolset#delivery-channels).

## 3. The turn boundary

<Warning>
  Delimit **turns**, not tasks. Score history is keyed per session, so a loop that fires turn-end once per task gives the [trajectory gate](/harness/loop/evaluation#the-trajectory-gate) exactly one sample per series — it can never reach `gate_window`, and nothing will ever fire. This is the easiest way to silently disable detection altogether.
</Warning>

Three equivalent styles — pick whichever fits your loop:

```python
# Async context manager (fires turn-end even on exceptions):
async with harness.turn(session_id):
    await my_agent_step(...)

# One-shot runner:
result = await harness.run_turn(session_id, my_agent_step, ...)

# Decorator:
step = harness.turn(session_id)(my_agent_step)
```

Or call the hook directly with a raw payload — the `end_state` you pass is what the [outcome verifier](/harness/closed-loop/outcome-verifier) receives *and* what a captured eval case carries as its replay input:

```python
harness.on_turn_end({
    "session_id": session_id,
    "turn_index": turn_index,
    "end_state": {"task_id": task_id, "task": user_input},
})
```

<Note>
  Use the **same session id** for the harness turn and the SDK trace context (`pandaprobe.session(session_id)`) — the evaluation scores whatever traces landed under that session.
</Note>

## 4. The barrier (recommended)

Turn-end is fire-and-forget by default. To make a lesson take effect *inside* the session, await the turn's self-heal cycle:

```python
async with harness.turn(session_id, settle=True):
    await my_agent_step(...)
```

or explicitly, when you want the diagnosis back:

```python
harness.on_turn_end({...})
result = await harness.settle(session_id)

if result.report is not None and result.report.gate_breached:
    for score in result.report.alerting_scores:
        log.info("tier %s %s=%.2f %s", score.tier, score.metric, score.value,
                 score.conditions)
if result.timed_out:
    log.info("barrier expired; work continues detached")
```

The barrier has its own generous budget (`barrier_timeout_s`, default `180s`), separate from `drain_timeout_s`. On expiry the work continues detached and `timed_out` is set — a slow platform costs you latency, never correctness.

<Note>
  **`settle()` consumes the turn's pending evaluation.** If you settle and then settle the *same* turn index again to fetch the report, the second call finds no new traces and returns an impoverished one. Take the report from the call that did the work.
</Note>

## Determinism helpers

Everything after `on_turn_end` is detached and non-blocking. When a test or script needs to observe results deterministically:

```python
await harness.refresh(session_id)      # join this session's in-flight evaluation (bounded)
await harness.refresh_all()            # join every in-flight evaluation
await harness.drain_validation()       # join in-flight candidate validation
harness.hook.pending_sessions          # sessions with work still in flight
```

`refresh*` and `drain_validation` are best-effort joins on `drain_timeout_s` for callers' convenience — correctness never depends on them; each background task handles its own result. `settle()` is the one wait that is part of the design.

<Tip>
  Building a phase barrier ("has everything landed before I archive the workspace?"), poll `hook.pending_sessions` rather than reaching into the private task map — that is exactly what it exists for.
</Tip>

## Everything on the facade

| Surface | Purpose |
| --- | --- |
| `harness.system_context()` | The prompt preamble: skill root + References + banner. |
| `harness.toolset` / `harness.shell` | The 10 operations; the restricted shell for sandboxed delivery. |
| `harness.turn(session_id, settle=False)` / `run_turn()` / `on_turn_end()` | Turn boundaries. |
| `harness.settle(session_id, timeout=None)` | The per-turn barrier → `SettleResult`. |
| `harness.refresh()` / `refresh_all()` / `drain_validation()` | Bounded best-effort joins. |
| `harness.run_regression(sample=None)` | Replay the eval set against the current rules. |
| `harness.validate_candidates()` | Run one candidate-validation round now. |
| `harness.mailbox` / `journal` / `rules` / `evalset` / `config` / `hook` | Direct store and hook access for inspection and scripting. |
| `harness.check_health()` | The memoized CLI/auth probe. |
